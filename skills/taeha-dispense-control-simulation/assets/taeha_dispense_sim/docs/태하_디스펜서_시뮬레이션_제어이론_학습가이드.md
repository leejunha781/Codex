# 태하 디스펜서 시뮬레이션·제어이론 학습 가이드

## 1. 결론

태하 디스펜서에는 MATLAB만이 정답은 아니다. 가장 현실적인 출발점은 다음 4층 구조다.

1. **Python 모델·자동시험**: 재료/노즐/온도 feed-forward, 센서 지연, shot-to-shot 보정, A/B 비율, CRC/이중화 데이터를 빠르게 검증한다.
2. **OpenModelica/FMI**: 모터–기구–압력–유체–온도 결합이 Python 경험 모델로 부족할 때 추가한다.
3. **Renode/SIL/PIL**: STM32 펌웨어의 상태기계, 통신, 타이머, 인터럽트, 저장 로직을 검증한다. Renode가 모델링하지 않은 아날로그·전력·기구는 증명하지 못한다.
4. **실제 보드 HIL·반복 토출**: ADC/DMA 지연, 모터 드라이브, 밸브, 로드셀, 정전 중 저장, 안전 출력을 최종 입증한다.

MATLAB/Simulink는 Simscape Fluids와 Simscape Electrical의 결합, 모델 기반 코드 생성, 요구사항·커버리지·정형 검증, Simulink Real-Time HIL이 조직의 실제 요구일 때 가장 강하다. PID가 필요하다는 이유만으로 MATLAB이 필수인 것은 아니다.

## 2. 제어 대상의 올바른 분해

    Target mass and A/B ratio
      -> profile feed-forward
      -> safety and constraint supervisor
      -> A/B actuator inner loops
      -> pump, pressure, valve, nozzle and mixer
      -> load cell and ADC filter
      -> stable-shot evaluator
      -> bounded shot-to-shot correction
      -> profile feed-forward

최종 중량 루프와 모터 PID를 혼동하지 않는다.

- 모터 전류/토크 루프: 가장 빠른 내부 루프
- 모터 속도 루프: 부하 변화 억제
- 모터 위치/회전량 루프: 스크루·피스톤·시린지 정량화
- 압력/유량 루프: 센서와 유체 지연의 제한을 받음
- shot 중량 루프: 안정 중량이 늦게 나오면 run-to-run 제어
- A/B 비율·안전 감독: 프로파일, 계측 유효성, 한계, 고장을 감시

## 3. feed-forward 기준값

프로파일 키에는 최소한 다음 항목이 포함되어야 한다.

- 재료명, A/B 성분, 제조 lot, 개봉/숙성 상태
- 밀도와 온도 범위
- 점도 또는 실험으로 확인된 공정 등급
- 노즐/믹서 형번과 유효 단면/길이
- 펌프·기어·스크루·시린지 형상과 감속비
- 모터/드라이브/제어 모드
- 공급 압력과 허용 범위
- 목표 중량 범위와 A/B 비율
- precharge, 속도/가속도, cutoff, valve timing, suck-back, settle time
- 보정 revision, 생성 근거, 유효 범위, 만료·재검증 조건

기준값은 다음 관계를 역으로 풀어 얻는다.

    command = inverse_model(
        target_mass,
        material_and_lot,
        density_and_temperature,
        nozzle_and_mixer,
        supply_pressure,
        pump_and_gear,
        actuator
    )

처음부터 복잡한 신경망을 쓰지 않는다. 실험점이 적으면 구간별 표와 선형/단조 보간이 더 감사 가능하고, 범위 밖 입력을 거부하기 쉽다.

## 4. 센서 지연을 포함한 중량 보정

총 지연은 다음의 합이다.

    L_total =
      fluid_transport
    + mechanical_response
    + load_cell_mechanics
    + ADC_digital_filter
    + task_scheduling
    + communication

특히 Σ-Δ ADC는 출력 데이터가 주기적으로 나온다고 해서 계단 입력에 즉시 정착하는 것이 아니다. 필터 차수와 설정에 따라 완전 정착에 여러 변환 주기가 필요할 수 있다.

안정 중량이 cutoff 이후에만 얻어지면 in-shot PID보다 shot-to-shot 보정이 우선이다.

    error_k = target_k - accepted_mass_k
    candidate = gain_k * (1 + alpha * error_k / target_k)
    gain_next = clamp(
        rate_limit(candidate, gain_k, max_delta_per_shot),
        gain_min,
        gain_max
    )

보정 금지 조건:

- ADC 오류, stale, saturation, NaN, 필터 미정착
- scale 불안정, 진동, 용기 접촉, outlier
- purge/prime/수동/재작업 shot
- motor slip, missed step, valve/pressure fault, 기포·cavitation·막힘
- 프로파일 불일치
- 최소 검증 중량 미만
- timeout, interlock, 비율 불량
- 보정 데이터 schema/CRC/profile 불일치

신뢰도는 단순히 최근 오차가 작다는 뜻이 아니다. 유효 sample 수, 환경 범위, 잔차, outlier, drift, 프로파일 일치, 최근 fault를 함께 반영한다.

## 5. PID를 적용할 위치

### 모터 내부 루프

- DC motor: current PI → speed PI → 필요 시 position PID
- BLDC/PMSM/ACIM: dq current PI/FOC → speed PI → position/trajectory
- stepper: 일반 open-loop step/dir 또는 encoder를 둔 closed-loop position/velocity
- 외부 servo drive: 드라이브가 내부 current/speed/position loop를 담당하고 STM32는 명령 인터페이스를 관리

정확한 모터/드라이브 인터페이스는 데이터시트와 배선으로 확인한다. “서보 모터”라는 이름만으로 pulse/dir를 추정하지 않는다.

### 압력/유량 루프

센서 대역폭과 지연이 충분할 때 PI부터 시작한다.

- output·rate limit
- anti-windup
- derivative를 쓸 경우 measurement derivative와 필터
- bumpless transfer
- timestamp/freshness
- sensor fault fallback
- 모터/압력/기구 hard limit

### 최종 중량 루프

짧은 shot에서 delayed mass PID를 빠르게 조정하면 과잉 반응할 수 있다.

- 지연이 공정 time constant보다 작은가?
- cutoff 이후 tail을 예측할 수 있는가?
- 불확실성 범위에서 안정성과 overshoot가 허용되는가?
- 지연 변동이 predictor 모델 범위 안인가?

아니면 feed-forward + bounded shot-to-shot correction을 사용한다.

## 6. 적용 가능한 제어이론

| 이론 | 태하 적용점 | 채택 조건 | 주요 위험 |
|---|---|---|---|
| PI/PID | 모터, 압력, 유량 | 대역폭·지연 식별 | saturation, windup, noise |
| Cascade control | current-speed-position-flow | inner loop가 충분히 빠름 | loop interaction |
| Feed-forward | shot 기본량·cutoff·suck-back | 프로파일 데이터 확보 | 범위 밖 외삽 |
| Gain scheduling | 온도·점도·노즐·운전점 | 검증된 영역과 부드러운 전환 | 프로파일 혼합 |
| Smith predictor | 일정한 긴 지연 | plant·delay 식별 | model mismatch |
| EWMA/run-to-run | 안정 중량 기반 다음 shot 보정 | 반복 shot, 안정 계측 | drift/noise, high-mix 간섭 |
| ILC | 반복 시간 궤적 보정 | 동일 horizon·초기상태 | 비반복 disturbance |
| Kalman/EKF/UKF | 압력·유량·tail 상태 추정 | 관측 가능성과 noise model | divergence |
| RLS | 느린 gain/drift 식별 | 충분한 excitation | ill-conditioning |
| MPC | A/B·압력·actuator 제약 동시 처리 | 검증 모델·연산시간 | solver failure |
| State machine | prime/ready/dispense/settle/fault | 항상 필요 | hidden transition |

권장 순서:

1. 안전 상태기계와 hard limits
2. 프로파일 feed-forward
3. 안정 중량 판정과 bounded run-to-run correction
4. A/B 독립 보정과 ratio supervision
5. 정확한 모터 내부 루프
6. 측정이 허용하는 경우 압력/유량 PI
7. 잔여 요구가 있을 때만 Smith/ILC/observer/MPC

## 7. A/B 비율

목표 총중량 total과 목표 질량비 R=A/B이면:

    target_A = total * R / (R + 1)
    target_B = total / (R + 1)

각 성분을 독립적으로 측정하는 것이 가장 좋다.

- A/B 각각의 gravimetric 계량
- 각 성분용 검증된 유량계
- 독립 encoder/piston displacement와 압력/밀도/누설을 포함한 검증 모델
- 배치 전후 성분별 탱크 중량

혼합 후 총 중량만으로는 A와 B 두 미지수를 동시에 알 수 없다. 모터 step/time은 공정 지표는 될 수 있지만 계측 체인 전체를 검증하지 않고 비율 합격 판정에 사용하면 안 된다.

감시 항목:

- component별 startup lag와 minimum dose
- purge volume와 pre-mix fill
- density-versus-temperature
- pot life
- mixer pressure와 blockage
- 한쪽 empty/cavitation/slip
- ratio window 지속시간과 누적 편차
- fault 시 양쪽 동시 안전 정지와 잔압 해소

## 8. CRC와 이중 슬롯

권장 record:

    magic
    schema_version
    record_length
    profile_key_hash
    material/component/lot/nozzle/mixer identifiers
    units and scaling
    gain/offset/feed-forward tables
    valid temperature/pressure/target ranges
    confidence and accepted_sample_count
    sequence_number
    created_by/test provenance
    payload_crc
    header_crc or authenticated tag when required

이중 슬롯 A/B 절차:

1. 부팅 시 두 slot의 magic/schema/length/profile/CRC/sequence를 검사한다.
2. 가장 최신의 유효 slot을 선택한다.
3. 새 record는 비활성 slot에 쓴다.
4. read-back과 CRC를 검증한다.
5. 마지막에 commit marker 또는 metadata를 원자적으로 갱신한다.
6. 어느 단계든 정전되면 기존 유효 slot로 복귀한다.
7. 둘 다 무효이면 factory baseline 또는 calibration-required 상태로 간다.

CRC는 우발적 손상 검출용이다. 공격 방지와 진위성에는 서명/MAC, 키 보호, anti-rollback이 별도로 필요하다.

## 9. 시뮬레이션 실험

최소 sweep:

- 목표 중량: 최소, 명목, 최대
- 비율: 허용 범위 경계
- 온도: 프로파일 최소/명목/최대
- 노즐: 신품, 마모, 부분 막힘
- 재료: lot, aging, viscosity drift
- 공급: pressure 감소, empty, air
- actuator: servo, stepper, brushed DC, BLDC/AC
- 센서: noise, drift, saturation, freeze, delay
- task: jitter, queue overflow, communication delay
- 저장: bit corruption, wrong schema/profile, 정전
- fault: 한쪽 component 중단, motor slip, valve stuck, watchdog reset

비교 지표:

- bias와 표준편차
- 95%/99% percentile
- A/B ratio error
- rejected shot 비율
- 수렴 shot 수
- actuator effort와 saturation 시간
- constraint violation
- false accept와 false reject
- fault detection·safe-state 시간
- reset 후 복구

## 10. 실제 HIL

    Test orchestrator
      -> production STM32 board
      -> motor/servo drive fixture
      -> programmable load-cell/ADC stimulus
      -> valve/pressure/temperature/safety-I/O fixture
      -> fault injection and synchronized capture

필수 항목:

- production build와 firmware hash
- board/fixture revision
- motor output은 초기 비활성
- probe serial과 target 확인
- raw ADC·filtered mass·command·state·fault timestamp
- 정전 주입 가능한 NVM fixture
- open/short/stuck/freeze/overflow/timeout
- watchdog와 brownout
- fault 해제 후 자동 재가동 금지
- 복원 절차와 fixture self-test

## 12. 실행 예제

본 폴더의 Python 모델은 다음을 실행한다.

- A/B 독립 feed-forward
- 온도·노즐 flow factor
- actuator별 lag/deadband/quantization/slew
- fluid lag, transport delay, dribble
- delayed/noisy load-cell measurement
- profile-isolated bounded shot-to-shot gain
- A/B ratio gate
- CRC32 dual-slot persistence
- 반복 shot CSV/JSON/PNG

기본 데모 40 shot의 마지막 10 shot 평균 절대 총중량 오차는 약 0.132%까지 수렴했다. 보정 미사용 데모의 같은 지표는 약 8.05%였다. 이는 데모 파라미터 내부의 SIMULATED 결과이지 태하 실제 장비 성능이 아니다.
